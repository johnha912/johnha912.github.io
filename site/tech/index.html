keeploop

Your AI proposes the change; a fixed metric decides if it stays.

A small open-source Python tool that makes AI coding assistants prove their work. It works with Claude Code, Codex, Cursor, and Gemini CLI, has no dependencies, and installs from PyPI with pipx install keeploop. MIT license.

Python 3.10+ / git / pytest / GitHub Actions / PyPI

View on GitHub (opens in a new tab) PyPI (opens in a new tab)

  1. Propose. The AI proposes one change at a time.

  2. Score. An evaluation script you approve scores it.

  3. Keep. The change stays only if it beats the best score by more than the evaluation’s own measured noise.

  4. Revert. Otherwise it is undone and a lesson is logged.

    datafromzero

    From A1 to AI — a free, open roadmap for learning data from zero, for people who only know spreadsheets. Four foundation stages (Excel and Sheets, SQL, Python, and an advanced core of statistics, Git, data modeling and cloud basics), then four career tracks: Data Analyst, Data Engineer, Data Scientist, and ML / AI Engineer. 208 lessons are published, and version 1.0.0 is archived with a DOI so a lesson can be cited.

    The Data Engineer track (31 lessons) builds one pipeline repository checkpoint by checkpoint — landing data from an API and from files, incremental and idempotent loads, quality gates that stop a run or quarantine a row, Airflow, dbt and Spark — and the ML / AI track has its own starter repository. Lesson pages ship no JavaScript beyond the framework’s own, and a mobile Lighthouse run (performance ≥ 90, accessibility ≥ 95) is an enforced build gate. Content CC BY 4.0, code MIT.

    Astro / Starlight / TypeScript / Python / uv / dbt / Airflow / Spark / GitHub Actions

    JOIN Order Optimization

    v2, my solo rebuild: a reproducible benchmark that forces and times every join order of four TPC-H chain queries on DuckDB and Postgres 17, then compares a textbook dynamic program, a greedy heuristic, and each engine’s own optimizer against that brute-force ground truth. A dbt-duckdb warehouse with key and foreign-key tests, GitHub Actions CI, and an interactive Plotly report.

    v1, CS 5800 Algorithms (Nguyen Ha and Yanglin Hu): a chain-query optimizer using the Θ(n³) matrix-chain dynamic program, compared with greedy and left-to-right orders on four SQLite databases. On Sakila, left-to-right does 150.88× more intermediate work than the optimum.

    Python / DuckDB / Postgres 17 / dbt / Plotly / SQLite
