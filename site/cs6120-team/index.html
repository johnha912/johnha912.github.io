📏 How projects are scored — the rubric

Every candidate gets a Project Score (0–100) = the sum of the 8 components below. Each component is scored on evidence at three anchors — 0 (absent / wrong), half (present but unverified or vague), full (verified against a concrete source). A point with no evidence line behind it scores 0.

The big number on each card is the Final Score = Rubric Score + Vote Bonus (max 100) — that is the ranking number. Only real team votes count; test/system votes never enter the tally.

Verdicts: keep score ≥ 80 and no fatal blocker · discard 65–79 (or ≥ 80 but beaten by a stronger same-family keep) · crash infeasible — no valid data, compute over budget, or a scope that cannot fit in 3 weeks.

Hard gates — fail one and a project cannot be a final keep, whatever its score (until cleared it is only a provisional keep*):

  • G1 · Data verified — the main dataset's page was opened / a sample downloaded, with name + license + access path recorded. Unverified caps the Data component at 4/10.
  • G2 · Red Team — challenged directly by someone who did not propose it, and the critique is on record.
  • G3 · Real-time inference endpoint — the project must describe exactly how live inference is served (stack + hosting + input/output + latency). Pre-recorded results fail. The only exception is a declared S25-style paper route, which swaps in a novelty + SOTA-comparison bar instead.
  • G4 · Data scale — corpus/eval at the precedent scale (≥ ~10k samples) or a written equivalent justification; otherwise Data ≤ 4/10 and no final keep.
  • G5 · Reproducibility — automated data download, a container plan, a replicable README, and citations for data + borrowed code.

Second layer: Elite /10 (would the problem → hypothesis → experiment → metric chain hold up at a frontier lab?) and Future Leverage /10 (paper, portfolio, or follow-on project potential). These two only reorder projects that already pass every gate — they never rescue a failed gate, and neither do votes: a bonus never overrides a gate or a crash verdict. Scores are append-only: a re-score is a new experiment, never an edit of history.

🔬 Top 10 — project analysis & scorecard

A separate breakdown of the ten leading projects: what each one analyzes, what the team would actually do, and how it would be built — with the full scoring line for each. Scores match the candidate board below, which keeps the complete pool.

#1 — C07 MCP tool-use security 91 keep

Rubric 89/100 · Elite 8/10 · Future 9/10 · Vote bonus +2 (1 team vote) · Final 91

What it analyzes: How often MCP tool-use agents fall for attacks across the tool pipeline — prompt injection in tool descriptions, name collisions, out-of-scope parameters — and whether a guardrail layer cuts the attack success rate (the source benchmark peaks at 75.8%) without hurting normal task performance (the NRP trade-off).

What the team does: Build an agent wired to 5–8 self-written tool stubs (search, calculator, files, fake calendar — no real data), implement the guardrails, and run the attack matrix with and without them.

How it is built: Option B agent on Cloud Run (L4 when the model is called), self-hosted Qwen ≤4B, all tools local stubs; live red-team demo. GCP cost ≈ $3–13 of the $50 credit. Canon anchor: W4 MCP security.

#2 — C11 Autoresearch loop for RAG pipeline 88 keep

Rubric 86/100 · Elite 7.5/10 · Future 8.5/10 · Vote bonus +2 (1 team vote) · Final 88

What it analyzes: Whether an autonomous propose → test → keep/discard loop genuinely improves a RAG pipeline on a fixed eval set — and whether the gains survive a sealed held-out set (the generalization gap), with an audit of the loop's own kept edits for reward hacking.

What the team does: Run the loop over pipeline variants (chunking, retrieval, prompting), keep only eval-passing edits, then audit every kept edit against the held-out set.

How it is built: The served artifact is the winning pipeline (Option A) on Cloud Run L4 — Qwen2.5-1.5B-class generator + small embedders; HotpotQA eval 500 + sealed 500 from the 7,405-question validation split; the loop itself runs offline on Explorer HPC. GCP ≈ $5–13. Canon: W3 Autoresearch (this team's own presentation) + W10 RAG.

#3 — C01 Agentic RAG self-correcting multi-hop QA 87 keep

Rubric 87/100 · Elite 7.5/10 · Future 8/10 · no team votes yet · Final 87

What it analyzes: The accuracy–latency–cost trade-off between naive RAG and self-correcting variants (reflection, corrective retrieval) on multi-hop questions, compared at matched token budgets so the comparison is fair.

What the team does: Build the retriever and three pipeline variants, run matched-budget ablations, and score answer EM/F1, supporting-fact F1 and joint F1 — all deterministic metrics, no judge needed.

How it is built: Option A on Cloud Run L4, one container: Qwen2.5-1.5B-Instruct + bge-small / MiniLM embedders over HotpotQA (90,447 train / 7,405 validation, CC BY-SA 4.0); the live endpoint lets visitors switch variants. GCP ≈ $5–13. Canon: W10 RAG (Lewis).

#4 — C25 Authorization alignment 85 keep

Rubric 85/100 · Elite 8/10 · Future 9/10 · no team votes yet · Final 85

What it analyzes: How often agents exceed the authorization they were given — 19.2% of trajectories in the source benchmark, with benign pressure causing more overreach than malicious injection (23.5% vs 17.6%) — and whether a contract check at action time, plus a consult-the-principal step, brings the rate down (14.0% vs 21.6% in the source).

What the team does: Build an authorization-aware sandbox and contract parser over a capped slice of the 286 tasks, then run the benign vs malicious pressure arms and the consult arm.

How it is built: Option B agent on Cloud Run L4 with a deterministic effect-boundary check inside the request path; the proposal pins the served model (self-hosted Qwen3-4B/8B) per the GCP-fit fix. Dataset CC BY 4.0, co-authored at Northeastern. GCP ≈ $5–13.

#5 — B2 RAG QA over course documents 84 keep

Rubric 84/100 · Elite —/10 · Future —/10 · no team votes yet · Final 84

What it analyzes: Which retrieval configuration (chunking, embedding model) answers questions over course documents best — with a recorded caveat: its ~40 self-written questions over a self-chosen corpus may saturate retrieval, so the comparison can lose signal.

What the team does: Collect the course / university document corpus, ingest it, build the retriever + generator, and run the configuration comparison with an evaluation harness.

How it is built: The textbook Option A: Cloud Run L4, MiniLM / bge embedder + Qwen2.5-1.5B in one container, live Q&A showing retrieved passages as evidence. GCP ≈ $5–13. Gauntlet verdict: CUT from the #5 race on measurement validity — it remains the pool's safest delivery hedge. Elite / Future: not scored.

#6 — C03 LLM judge reliability in context 84 keep

Rubric 84/100 · Elite 8/10 · Future 8/10 · no team votes yet · Final 84

What it analyzes: Whether LLM judges give consistent verdicts when the context and the order of the two answers change — consistent accuracy under position swap — and whether three fixes (priority-ordered rubric, pairwise swap, self-consistency voting) actually help.

What the team does: Replicate the benchmark (2,000 pairs × 2 orders = 4,000 judge calls), implement and evaluate the three fixes, and hand-label 200 samples for a human-agreement check.

How it is built: The product is a judge wrapper on Cloud Run L4: Qwen3-8B judges both orders inside the request and returns the verdict plus a live consistency flag on the visitor's own example. Data: ContextualJudgeBench, 2,000 pairs, CC-BY-4.0. GCP ≈ $5–13. Gauntlet verdict: ADVANCE — the insurance pick (#6).

#7 — C05 Budget forcing for small models 84 keep

Rubric 84/100 · Elite 8/10 · Future 8.5/10 · no team votes yet · Final 84

What it analyzes: The dose–response curve of test-time compute: how a small model's accuracy changes as its thinking-token budget grows (512 → 4k), in English vs Vietnamese, with Thai as a no-translation control — the s1 budget-forcing question, transferred to off-the-shelf models.

What the team does: Build the budget-forcing harness, run the English arm on GSM8K, self-translate 250 items into Vietnamese in MGSM style with a human check (a Week-1 kill-gate), then sweep budgets × models.

How it is built: vLLM serving Qwen3-4B (the 8B arm also fits) on Cloud Run L4; the demo is a live budget slider that streams the reasoning trace while the accuracy-vs-budget curve updates. Data: GSM8K (MIT); MGSM has no Vietnamese config, hence the team-built arm. GCP ≈ $13. Gauntlet verdict: ADVANCE — recommended #5.

#8 — C19 Epistemic humility under knowledge conflict 84 keep

Rubric 84/100 · Elite 7.5/10 · Future 8/10 · no team votes yet · Final 84

What it analyzes: Epistemic humility under knowledge conflict: when retrieved passages disagree, does the agent identify the conflict, still solve correctly, and escalate when it should (the Identify / Solve / Escalate rates) — and do humility interventions cost accuracy?

What the team does: Construct controlled conflicts by documented passage substitution over HotpotQA, code agent trajectories with two coders plus an agreement statistic, and compare a baseline against a conflict-flag + escalation arm.

How it is built: Option A RAG endpoint on Cloud Run L4 that exposes the agent's conflict flag and escalation state live on the visitor's question. GCP ≈ $5–13. Gauntlet verdict: HOLD — in contention behind C05 / C03 / C44.

#9 — C23 Scoped constraints 84 keep

Rubric 84/100 · Elite 7.5/10 · Future 7.5/10 · no team votes yet · Final 84

What it analyzes: The false-pass gap between checking a whole response and checking constraints where they were scoped: models pass global checks while violating the one section a constraint belonged to.

What the team does: Replicate the whole-vs-scoped gap on the verifiable-constraint subset (the headline), run judged constraints as a calibrated secondary arm, and optionally test constraints as a reward signal.

How it is built: A live console on Cloud Run L4: a small model drafts from a topic + outline, and the page shows both verdicts side by side with the violating span highlighted. Data: LIFT-Bench, 784 tasks (LIFT-Train 34,258), public code. GCP ≈ $5–13. Gauntlet verdict: HOLD — checker-family backup behind C03.

#10 — C37 Right Outcome Wrong Process 84 keep

Rubric 84/100 · Elite 7.5/10 · Future 8.5/10 · no team votes yet · Final 84

What it analyzes: Process compliance: agents that reach the right outcome while skipping required steps — 55.5% of executions in the source benchmark are false-passes (outcome-pass, process-fail) across six regulated domains.

What the team does: Stand up one simulated regulated workflow end-to-end (runtime, customer simulator, both graders), run the model sweep, and build a taxonomy of skipped obligations.

How it is built: Option B agent on Cloud Run with a dual-verdict panel — a final-state checker plus a hybrid grader (deterministic ordering/authority checks + an LLM judge) — rendering the trace with the skipped obligation highlighted against its rule card. Data: CXBench, 120 tasks / 53 rule cards, public code. GCP ≈ $5–13. Gauntlet verdict: CUT from the #5 race (panel composition; its headline also needs a judge-calibration arm).
